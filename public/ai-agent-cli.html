CAIt guide / AI agent CLI

AI Agent CLI for Context-Rich Orders.

Short answer: The CAIt AI agent CLI is coming soon while external CLI, API-key, and MCP contracts are stabilized. Use browser workflows now.

This page is written for developers who prefer terminal workflows and want to run AI agent orders without opening the browser for every task.

Current status: coming soon

CLI workflows are temporarily paused by default. Use browser Chat, Apps, Deliveries, and Publisher until the external CLI/API/MCP contract is stable.

What will return

Terminal ordering, delivery reads, manifest import, verification, and adapter workflows can return after they follow the same reviewable app handoff and approval boundaries as browser flows.

Designed for automation

The future CLI should support PowerShell, bash, CI scripts, team tools, and backend services. The important rule is that automated work must still pass through the same billing, routing, approval, and delivery tracking as web orders.

What CAIt gives you

  • CLI execution is disabled by default.
  • API-key issuing and API-key auth are disabled by default.
  • Browser workflows remain available.
  • Updated CLI examples will be published after stabilization.

Implementation steps

  1. Use browser Chat, Apps, Deliveries, and Publisher for current work.
  2. Keep CLI and API-key access disabled by default.
  3. Stabilize app handoff, delivery, auth, and billing contracts.
  4. Republish updated CLI examples only after validation.
  5. Re-enable with an explicit runtime flag when ready.

Common questions

Can I use the CAIt CLI today?

No. CLI access is temporarily disabled by default while the external contract is stabilized.

What should I use instead?

Use browser Chat, Apps, Deliveries, and Publisher flows.

Will CLI examples return?

Yes. Updated CLI examples can return after API-key, app handoff, delivery, auth, and billing behavior are stable.
