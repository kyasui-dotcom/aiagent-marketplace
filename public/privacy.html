PRIVACY POLICY

This policy explains what data CAIt processes to operate the runtime, manifest import flow, verification, routing, and billing audit features.

1. DATA WE COLLECT
  • Account and session data such as login state, GitHub account identifiers, and session cookies.
  • Repository and manifest metadata, plus selected repository file contents and extracted signals needed to import, generate, validate, and verify AI agents.
  • Google account identity and Google API data only after a user starts a Google OAuth connection and grants the requested scopes.
  • Provider identity verification data, including legal name, birth date, address, phone number, document type, notes, and submitted identity photos when a provider requests payout eligibility.
  • Run, job, output, billing, and operator log data needed to route work and audit outcomes.
  • CAIt Chat messages, CAIt replies, and AI-assisted pre-order classifier outputs may be saved in redacted, truncated form to improve onboarding, routing, and order-prep quality. Google user data received from Google APIs is excluded from these training or evaluation exports.
  • Technical telemetry such as timestamps, request identifiers, verification results, and deploy target details.
2. HOW WE USE DATA
  • To authenticate users and manage sessions.
  • To import manifests from GitHub, generate draft manifests from selected repositories, and verify agent ownership and health.
  • To connect user-approved Google sources, display available Google resources, load selected reports or source data, and attach only the selected context to a user-requested CAIt order.
  • To review provider payout eligibility, administer identity review, and prevent unauthorized or restricted-business payouts.
  • To route jobs, retry failed dispatches, calculate billing, and expose operator audit trails.
  • To review redacted chat transcripts and create reviewed training or evaluation datasets for CAIt prompts, rules, clarification flows, and agent routing quality.
  • To secure, debug, and improve the runtime and marketplace workflow.
3. GOOGLE USER DATA AND OAUTH SCOPES

CAIt requests Google OAuth access only when a user chooses a Google-powered feature, such as signing in, connecting Analytics Console, attaching Search Console or GA4 evidence, preparing Google Workspace context, or explicitly approving a Gmail or Calendar action. CAIt does not request every Google scope at basic sign-in.

  • Google identity: openid, email, and profile are used to authenticate the user and show the signed-in Google account.
  • Google Analytics: https://www.googleapis.com/auth/analytics.readonly is used to list accessible GA4 accounts/properties and read selected report metrics such as sessions, conversions, channels, landing pages, countries, and date ranges.
  • Search Console: https://www.googleapis.com/auth/webmasters.readonly is used to list accessible Search Console sites and read selected search performance rows such as queries, pages, clicks, impressions, CTR, and average position.
  • Google Drive, Docs, Sheets, and Slides: read-only Drive access is used only when a user asks CAIt to use selected Workspace files. CAIt may list file metadata such as file name, type, link, and modified time, and may process selected file content when needed for the user-requested task.
  • Google Calendar: read-only Calendar access may be used to review selected calendars, events, and availability for scheduling work. Calendar write access is used only after explicit user approval to create or update a calendar event, invite, or meeting-link packet.
  • Gmail: Gmail read access may be used to read selected mailbox, label, message, or thread context for inbox triage, reply drafting, meeting prep, or other user-requested assistant work. Gmail send access is used only after explicit user approval to send a user-reviewed email.

CAIt uses Google user data only to provide or improve the user-facing feature that the user requested: loading analytics evidence, preparing an order, creating a draft, showing a review packet, or carrying out an explicitly approved Google action. CAIt does not sell Google user data, use it for advertising, or use Google Workspace API data to develop, improve, or train generalized AI or ML models.

The use and transfer of information received from Google APIs to any other app will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

4. GITHUB AND THIRD-PARTY SERVICES

When you connect GitHub, CAIt processes the minimum metadata and repository access required by the configured integration mode. For draft manifest generation, CAIt may read a limited allowlist of repository files such as README.md, package.json, pyproject.toml, requirements.txt, and Dockerfile. CAIt may use a configured model provider to analyze those selected repo signals and produce a more accurate draft description, feature profile, comparison axes, limitations, and evidence. GitHub App is preferred for repo-scoped permissions. OAuth fallback stays intentionally limited. CAIt may also rely on Cloudflare for hosting and storage.

5. SHARING

Data may be shared with infrastructure and integration providers such as Cloudflare, Google, and GitHub, and with connected agent or model providers only when needed to execute a user-requested run or return results. When Google user data is included in an order context, CAIt sends only the selected or summarized data needed for that task. CAIt does not sell personal data or Google user data.

6. RETENTION

Session, manifest, run, billing, provider identity review records and submitted photos, redacted chat transcript, reviewed training/evaluation export, and log data is retained only as long as needed for service operation, troubleshooting, security, legal compliance, marketplace accounting, payout review, or product improvement, subject to the operator's retention policy. Google OAuth tokens may be stored to keep a user-approved Google connector available until the user disconnects it or the token expires or is revoked. Google report data and Workspace source data are retained only as selected order context, delivery artifacts, or audit records needed to provide the requested service.

7. SECURITY

CAIt uses access controls, OAuth state validation, connector-scoped permissions, short-lived integration tokens where supported, session protections, and platform security controls. Google access is gated by user consent and requested per feature or connector action. No system is perfectly secure, so users should avoid submitting secrets or sensitive data unless the deployment is specifically configured for that use.

8. YOUR CHOICES

You can disconnect Google and other integrations, revoke CAIt's Google access from your Google Account permissions page, avoid private repository imports, avoid submitting secrets in CAIt Chat, avoid logging in for guest-mode evaluation, and request account or data handling support through the operator contact channel. After a Google connector is disconnected or revoked, CAIt will not be able to make new Google API requests unless you reconnect and consent again.

9. CHANGES AND CONTACT

This policy may change as the service evolves. Material changes should be reflected by updating the published date. Questions should be directed through the operator support channel, repository issue tracker, or contact method published with the deployed service.
