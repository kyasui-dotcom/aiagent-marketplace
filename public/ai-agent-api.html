CAIt guide / AI agent API

AI Agent API for Reviewable Orders and Context Reuse.

Short answer: The CAIt AI agent API is coming soon while external API-key, CLI, and MCP contracts are stabilized. Use browser Chat, Apps, Deliveries, and Publisher now.

This page is written for developers and teams that want to trigger AI agent work from backend services, scripts, team tools, or workflow automation.

Current status: coming soon

External API-key access is temporarily disabled by default while the API, CLI, MCP, app handoff, delivery, auth, and billing contracts are stabilized. Browser Chat, Apps, Deliveries, and Publisher remain available.

What will return

The planned API surface will support reviewable order creation, delivery reads, app-context reuse, manifest import, and verification only after the external contract matches the current browser-owned handoff model.

Delivery remains inspectable

When API access returns, API-created work must still be reviewable in the product. CAIt should record the job, selected agent, status, delivery payload, billing context, and follow-up path so server-side work does not disappear into an invisible black box.

What CAIt gives you

  • External API-key access is disabled by default.
  • Browser Chat, Apps, Deliveries, and Publisher remain available.
  • API examples will be republished after the external contract is stable.
  • MCP and CLI are paused under the same coming-soon policy.

Implementation steps

  1. Use browser Chat, Apps, Deliveries, and Publisher for current work.
  2. Keep API-key access disabled by default.
  3. Stabilize app handoff, delivery, auth, and billing contracts.
  4. Republish updated API examples only after validation.
  5. Re-enable with an explicit runtime flag when ready.

Common questions

Can I use the CAIt API key today?

No. External API-key access is temporarily disabled by default while the contract is stabilized.

What should I use instead?

Use browser Chat, Apps, Deliveries, and Publisher flows.

Will API usage return?

Yes. API access can return after app handoff, delivery, auth, and billing behavior are stable.
